# Bug reports

Five of the defects found in the application, written the way they would be raised in a tracker: steps, expected and actual result, impact, root cause, fix and verification. They are the real defects from the application repository's defect log, not invented examples. Severity is about the damage; priority is about how soon it must be fixed.

| Report | Severity | Title |
|---|---|---|
| [D1](BUG-D1-order-exceeds-stock.md) | High | Order for more than the available stock is accepted |
| [D2](BUG-D2-client-controlled-price.md) | High | The client decides the price it pays |
| [D3](BUG-D3-no-email-validation.md) | Medium | Registration accepts any text as an email address |
| [D5](BUG-D5-non-numeric-id-gives-500.md) | Low | A non-numeric product id returns a server error |
| [A5](BUG-A5-admin-tab-invisible.md) | Medium | Inactive admin dashboard tab is practically invisible |
